# Dynamo Feed — PRD

## Original Problem Statement
Personal portfolio "Dynamo Feed" styled as a short-video app: centre = feed of cartoon "reels"; left = condensed portfolio; right = "Off the clock". Frontend only, static, Vercel-hostable. React + Vite + TypeScript + Tailwind + Framer Motion. Content from zod-validated JSON files in src/content.

## Design (v2 — current)
Warm dark rounded theme: bg #211C1F, surfaces #2B2428, raised #352C30, cream #F2EAE2, muted #B9ADA6; sage #93B29C (deep #1A3122), rose #D96A6A; cast pastels: reginald #C7B3D9, blaze #E0A58C, marge #DEC490, tia #D9A5AE, saurav #A9BED6. Nunito display / Inter body. desk breakpoint 1200px.

## Architecture
- Vite 6 + React 19 + TS in /app/frontend. No backend. Content: src/content/{profile,now,reels,cast,autoScripts}.json + schemas.ts (zod, fail-loud) + index.ts (profileItemBySlug, timeAgo).
- Columns are thin renderers; every card is its own component:
  - src/components/cards/: CardTitle (shared), NowReadingCard, WatchThisCard (wraps ../SwipeDeck), LatestWritingCard, VolunteeringCard, LearningSpanishCard — RightColumn renders the list in order, reads now.json.
  - src/components/profile/: ProfileHeader, SocialLinks, StatsStrip, CollapsibleSection, ItemCard, FooterCta — LeftColumn renders the list in order, reads profile.json, owns open/highlight state + event listeners.
- Components take data as props; only column files read JSON. README "How to edit" documents add/remove/reorder.

## Cast & CharacterSlot (fixed 2026-11-02)
- cast.json has headroom per character (fraction of frame height above the drawing): reginald 0.29, blaze 0.33, marge 0.43, tia 0.31, saurav 0. Marge scale 1.2→1 (was covering content).
- Box height = heightPercent × scale ÷ (1 − headroom) → VISIBLE character = heightPercent × scale (templates pass 40).
- Waist characters (Tia): NO 200% box — same box as full, anchored flush to the reel's bottom edge (her sheet art is pre-cut at the waist).
- align prop ("left"|"center"|"right", default center) replaces fixed left:16.
- Name chip REMOVED from CharacterSlot; speaker name shows in the caption area (NAME ONLY — no role/personality, per user).

## Unified template layout (one layout for every template)
- Top zone (0–35%): template card/graphic — review card, myth card, news banner, stat number, doc title, chat bubbles (storytime exception: 8%→50%).
- OVERLAP RULE (all templates): top-zone cards end above the character's head with a gap — headTopPercent(characterId, heightPercent) helper (CharacterSlot.tsx) computes the head line from size+framing; review + myth cards sit in maxHeight/overflow-hidden wrappers (headTop−5%). Content shows only the latest lines (older faded 0.55) instead of growing over the character (fixed Marge's review card).
- Middle: character on the ground line just above the caption zone (full) or flush bottom (waist).
- Caption zone (bottom 22%): speaker name (data-testid=speaker-name, NAME ONLY — no role) + profile chip in the same row (ProfileReelChip) + progress bar at the very bottom. Storytime shows ONLY the name row — its bubbles are the caption (last TWO including the current line, older faded 0.6, typing indicator for the first 700ms of each beat).
- Every template renders ReelBackground (breaking news does too). Breaking news: spoken line is the caption; caption column = ReelCaption + lower-third; ticker at the bottom.
- StatReveal: pause-aware count-up — accumulator freezes mid-count on pause and RESUMES from the same point; final value shown when inactive/not counting (never stuck at 0).
- PAUSE FREEZES EVERYTHING: PausedContext (PausedProvider/usePaused) from ReelPlayer (paused && active). Freezes: sprite idle bob, squash-on-pose, mount slide (renders final state while paused), Reginald 180ms flip, news ticker + typing dots (CSS animation-play-state:paused), stat count-up (resume-from-point), entrance animations (initial={false} while paused). Unpause resumes all.
- READING TIME: beatDurationMs(beat, template) in content/index.ts = clamp(1200 + 55×caption.length, 2500, 7000), storytime +700ms typing lead-in, beat.durationMs only wins when longer, audio metadata overrides when present. The continuous progress bar follows the computed total.
- NudgeTemplate (template "nudge", slug talk-to-the-human): message + Email/LinkedIn/Resume buttons.

## Left column
Header (photo /avatar.svg fallback, name, one-liner, location chip) → SocialLinks (logo circles + sage resume circle) → StatsStrip → 5 collapsible sections (all collapsed, one open, counts; empty hidden): Experience, Projects, Writing and research, Community, Education and certifications → FooterCta "Talk to the human instead". ## Right column — "Off the clock"
Title + "Updated X ago" (pulsing dot, now.updatedAt) → NowReadingCard (cover fallback block, progress 0–100) → WatchThisCard/SwipeDeck → LatestWritingCard (hidden when empty) → VolunteeringCard → LearningSpanishCard.

SwipeDeck (swipe-away only — simplified 2026-11-02, no "previous" behaviour): every control does the same thing — the top card flies off in ITS direction (swipe left / left arrow / left key / left chevron → exitX −480; swipe right / right arrow / right key / right chevron → +480) ON TOP of the pile (exit zIndex 3, enter zIndex 1 beneath, pile z-0), and the next card settles into place from the pile (enter = pop, no slide-in-from-left variant, no direction state); the deck loops endlessly (a full cycle brings any card back); no drag snap-back during the exit (no constraints, dragSnapToOrigin=false, sub-threshold drags spring back via animate(x,0)); new swipes/clicks/keys are ignored until the fly-off finishes (busyRef reset in onExitComplete, mode="sync"). Layout: deck area h-60 fixed; top card h-[calc(100%-20px)]; two cards behind SAME size, scale 95%/90%, moved down 8px/16px, rotated ∓2° — thin edges peek at the bottom, everything inside the deck area; "Swipe for more" hint (Hand icon) sits 12px below the deck area, nothing covers it, hidden after first commit. One-time wiggle (deck-wiggle-once CSS keyframes: −40px → +40px → settle, 1.2s, 450ms after first in-view) skipped under reduced motion (hint text stays). Grab/grabbing cursor; DeckCard sub-component owns its own x/rotate motion values so exiting and entering cards never share drag state.

- Generator src/feed/autoReels.ts builds reels at runtime from now.json; wording lives in src/content/autoScripts.json. Per kind (reading / watch / spanish / volunteering / writing): 2–3 script variants (template + hostId + beats with character/pose/caption + optional data for the template), a comment pool (cast voices), and for spanish a milestoneScript used when streak % 100 === 0 (extra hype).
- Placeholders {title} {author} {progress} {take} {why} {year} {kind} {streak} {text} {status} {platform} filled from the item; stat data "value" becomes a number for the count-up.

- Every generated reel passes reelSchema (same zod validation as reels.json, throws at load on failure) and is marked auto: true.
- SKIP RULE: items with empty fields or fields containing "REPLACE" (case-insensitive) never become reels — current now.json placeholders yield only auto-spanish-600 + auto-volunteering.
- "New" chip (ReelPlayer, top-right, sage pill, data-testid=reel-new-chip) on auto reels while now.updatedAt is within 7 days (autoReelsFresh).
- Feed mixing in order.ts mixAutoReels: 2–3 autos per generation, seeded by the seam hash (deterministic per seam), inserted at position ≥ 2, never two autos in a row, no repeat within 5 positions across the seam. FIXED the pre-existing fallback hole: with only 7 base reels ~97% of shuffles break the seam rule, so all 30 attempts failed and the unchecked fallback shipped violating generations — the fallback now greedy-repairs the first five positions in place. Verified over 25 simulated sessions: 0 repeat-within-5, 0 auto-in-a-row.
- README "Auto-reels" section documents editing autoScripts.json and that updating now.json creates reels automatically.


## Voices (2026-11-02)
- Manifest-driven audio: public/audio/manifest.json maps {reelSlug}:{beatIndex} → "audio/<file>" (served from public/audio/, absolute /audio/… URLs). Fetched once at load (src/audio/engine.ts loadManifest, module-cached); a beat has audio ONLY if its key is present — missing files are never probed. Sample test file: public/audio/sample.wav (synth tone) on key breaking-built-by-voice:0.
- Sound OFF by default: "Tap for sound" sage pill (FeedFrame, bottom-[30%] left-3, data-testid=sound-pill) on the FIRST reel with audio; speaker toggle in ActionRail (data-testid=action-sound); choice remembered in localStorage dynamo:sound (try/catch). SoundProvider (src/audio/SoundContext.tsx) wraps FeedFrame (FeedFrame → SoundProvider + FeedFrameInner).
- Playback (sound on, per ReelPlayer): beat length = max(audio duration + 300ms, reading time) — sound off = pure reading time. One Audio element per player; its position always derives from elapsedRef (fresh beat → 0, resume → exact mid-beat offset); pause pauses audio, resume continues, scroll-away stops (active=false), every loop wrap bumps loopEpoch → audio restarts. Metadata loading per reel; failed file = no duration = silent reading-time fallback. Preload current+next reel (engine preloadAudio, dedup set).
- Mouths: engine exposes readLoudness (AnalyserNode RMS ×6 gain, 0..1); ReelPlayer samples it in the SAME rAF tick, smooths (0.35 lerp) into a loudness MotionValue, publishes via VoiceProvider/VoiceContext (src/audio/VoiceContext.tsx) with hasVoice = active && soundOn && current beat has audio. CharacterSlot: Reginald's neutral/talking flap is now LOUDNESS-THRESHOLD driven (0.3) when a voice plays (180ms timer only without voice); other characters get a small voice-scaled bob (y −5px max, nested motion.div); sound off/no audio = current timer behaviour.
- Generation: scripts/generate-voices.mjs (Node, never browser) — bundles scripts/reel-sources.ts (reels.json + feed/autoReels via esbuild, temp-file import), builds one job per beat ({slug}:{i}, cast.json voiceId per character), provider ADAPTERS with elevenlabs default (ELEVENLABS_API_KEY env, never committed; VOICE_PROVIDER/ELEVENLABS_MODEL_ID optional). Cache = sha1(characterId:caption) → public/audio/<hash>.mp3 — unchanged lines never regenerate; --force regenerates; --dry-run lists beats + char counts. Manifest entries only written for generated/existing files (a skipped voiceId job never leaves a dangling manifest key). Verified dry-run: 37 beats / 2425 chars, auto reels included.
- README "Voices" section: voiceIds in cast.json, env key, dry-run/generate/--force, caching, adapter interface.
